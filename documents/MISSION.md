# MISSION — 고정 장비 기반 랜덤 미션 명세

> 이 문서는 현재 저장소의 Gazebo 월드와 로봇 구성을 기준으로 **미션을 처음부터 다시 정리한 계약서**입니다.
> 대회/운영 측의 공식 규정이 별도로 공지되면 그 규정이 이 문서보다 우선합니다.
>
> 표기
> - **[고정]** 현재 월드·키트에 실제로 존재하는 장비/규칙
> - **[운영 가정]** 6개 발제팀 운영을 위해 이 문서에서 정한 가정
> - **[확인 필요]** 실제 대회 운영진과 맞춰야 하는 항목

---

## 0. 한 줄 요약

> **경기장과 장비는 고정되어 있고, 문제는 6개 팀이 각자 카드로 발제하며 경기마다 거의 랜덤하게 선택된다.**
> 로봇은 새 장비를 요구하지 않고, 아래에 적힌 **퍽·AprilTag·미션 태그·구역·신호등·사람 장애물**만 사용해서 주어진 문제를 수행한다.

핵심 원칙:

1. 문제는 미리 정해진 3~4개 목록이 아니다. **6개 팀이 고정 장비 안에서 자유롭게 조합해 발제**한다.
2. 로봇은 문제의 **문장/카드/활성 태그**를 보고 그때그때 목표를 해석해야 한다.
3. 퍽에는 **6면 모두 AprilTag가 실제로 박혀 있다.** QR 코드는 사용하지 않는다.
4. 문제 발제팀은 장비를 추가하거나 바꿀 수 없다. **있는 장비의 상태·조합만** 바꿀 수 있다.
5. 로봇은 시작부터 종료까지 **사람의 직접 조작 없이** 수행하는 것을 기본으로 한다.

## 2. 고정 장비

### 2-1. 퍽 (Puck)

| 항목 | 내용 |
| --- | --- |
| 기본 개수 | 9개 (3 red, 3 orange, 3 green) |
| 기본 크기 | **30 × 30 × 60 mm** 직육면체 |
| 태그 | **6면 모두** AprilTag 부착(박힘) |
| 태그 패밀리 | `tag36h11` |
| 퍽 면 태그 크기 | 약 28 mm |
| 색상 ID | **red=1, orange=2, green=3** |
| 같은 색 | 6면 모두 같은 ID |
| 구분 축 | **색상 + 눕힘/세움 자세** |
| 현재 기본 형상 | 직육면체 한 종류 |

> **중요:** 퍽은 색만 다른 것이 아니라 **눕힌 상태와 세운 상태**가 문제의 조건이 될 수 있다.
> 현재 키트의 기하 형상은 직육면체 한 종류이고, “모양” 문제는 **눕힘/세움 자세**로 정의한다.
> 향후 다른 기하 형상의 퍽이 지급되면 이 표에 형상별 태그 ID를 추가한다.

퍽의 태그는 단순 장식이 아니라 **색/종류를 식별하는 실제 센서 입력**이다.

- 상단·하단·4옆면의 태그가 모두 바깥을 향한다.
- 퍽이 누우면 옆면/상하면 태그가 카메라 쪽으로 드러난다.
- 퍽을 밀거나 들면 자세가 바뀌므로, 로봇은 태그와 자세를 함께 판단해야 한다.

### 2-2. 미션 태그

| 태그 ID | 이름 | 의미 |
| --- | --- | --- |
| 10 | `SORT_COLOR` | 색깔별 정리 |
| 11 | `MOVE_TO_B` | B 구역으로 이동 |
| 12 | `STAND_UP` | 누운 퍽 세우기 |
| 13 | `LAY_DOWN` | 선 퍽 눕히기 |
| 20 | `B_ZONE` | B 구역 표지 |

- 미션 태그는 스테이션 근처 벽면(`z ≈ 0.20 m`)에 붙는다.
- 큰 벽 태그는 약 120 mm, B 구역 태그는 그보다 작은 판으로 표시된다.
- **QR은 없다.** 문제의 primitive는 미션 태그와 문제 카드/`/gz_mission/info`로 전달된다.

### 2-3. 구역

| 구역 | 내용 |
| --- | --- |
| `RED` / `ORANGE` / `GREEN` | `SORT_COLOR` 스테이션 동쪽의 색별 정리 구역 |
| `B` | `MOVE_TO_B` 스테이션의 파란색 B 구역 + 벽 태그 20 |
| 퍽 군집 | 각 스테이션 중심 주변 |
| 미션 앞쪽 | 장애물/사람이 나오지 않도록 비워 둔 영역 |

### 2-4. 신호등

| 항목 | 내용 |
| --- | --- |
| 개수 | 2개 |
| 형태 | 상단 방 동서 통행로 위 **도로형 갠트리** (상부 빔 + 양쪽 기둥) |
| 위치 | `x = -0.75`, `x = 1.15`, `y = 2.75`, 높이 `z = 0.65` |
| 방향 | 렌즈가 로봇 진행 방향(서쪽 스폰 쪽)을 향함 |
| 주기 | 기본 3초 |
| 순서 | 빨강 → 초록 → 주황 |
| 두 신호등 | 위상을 엇갈리게 운용 |

문제 카드는 신호등을 **주행 조건**으로 사용할 수 있다. 기본 판정은 다음과 같이 둔다.

- **빨강**: 정지선/갠트리 앞에서 정지
- **초록**: 통과
- **주황**: 원칙적으로 정지. 이미 갠트리를 통과 중이면 안전하게 진행

현재 키트에는 별도의 바닥 정지선이 없으므로, 문제 카드에서 필요하면 “갠트리 중심 `x` 좌표 앞”처럼 정지 기준을 명시한다.

### 2-5. 사람 장애물 (동적)

| 항목 | 내용 |
| --- | --- |
| 형상 | 사람형 (원기둥 몸통 + 머리 + 팔·다리) |
| 기본 크기 | 220 × 220 × 600 mm |
| 동시 출현 | 최대 3명 |
| 수명 | 약 12초 |
| 출현 조건 | 로봇이 실제 이동 명령을 받고 움직이는 동안만 |
| 정지 시 | 즉시 제거 |
| 미션 앞쪽 | 스테이션 중심 반경 약 0.75 m에서는 출현하지 않음 |
| AprilTag | 없음 (퍽과 구분되는 동적 장애물) |

문제 카드는 “사람을 피해서 이동”, “사람이 지나간 뒤 출발” 같은 조건을 넣을 수 있다.
단, 미션 수행 중 로봇이 정지하면 사람은 사라지는 것이 현재 월드의 기본 동작이다.

### 2-6. 정적 장애물

- 중성색 박스 6개 + 실린더 6개
- 매 시작마다 미로 빈 공간에 무작위 배치
- 미션 구역/태그/신호등 갠트리와 겹치지 않게 배치
- 문제 카드는 이들을 “회피 대상”으로 사용할 수 있다.

## 4. 문제 발제 방식 — 6개 팀 랜덤

### 4-1. 기본 운영 가정

1. 발제팀은 **6개 팀**이다.
2. 각 팀은 고정 장비만 사용해 **문제 카드 1장**을 만든다.
3. 경기/세션마다 6장 중 **1장을 무작위로 선택**한다.
4. 선택된 카드의 목표만 로봇에 주어진다. 다른 카드의 목표는 숨긴다.
5. 발제팀은 문제 카드에서 **색, 개수, 순서, 구역, 신호 조건, 장애물 조건**을 바꿀 수 있다.
6. 로봇은 문제 카드에 없는 장비나 태그를 가정하면 안 된다.

> 실제 추첨 방식(6장 중 1장, 라운드별 1장, 난이도별 추첨 등)은 운영진이 정한다. 이 문서는 “랜덤하게 하나가 주어진다”는 전제만 고정한다.
>
> **현재 시뮬레이터 참고:** `/gz_mission/info`는 활성 미션과 스테이션 메타데이터를 제공하지만, 6개 팀이 쓴 자연어 카드 원문을 자동으로 해석하지는 않는다. 실제 운용에서는 문제 카드를 primitive 목록으로 변환하는 전달 규칙이 필요하다. **[확인 필요]**

### 4-2. 문제 카드 필수 항목

발제팀은 아래 형식을 채워야 한다.

```text
[문제 ID]
- 제목:
- 사용 스테이션/미션 태그:       예) STAND_UP(12), MOVE_TO_B(11)
- 대상 퍽:                       예) red 2개, green 1개 / color tag 1,3
- 초기 상태:                     예) 기본 월드 그대로 / 특정 퍽만 눕힘
- 요구 동작 순서:                예) STAND_UP → MOVE_TO_B
- 완료 조건:                     예) 모든 대상 퍽이 B 구역 안, 사람 충돌 0
- 환경 조건:                     예) 첫 갠트리는 초록일 때만 통과
- 제한 시간:                     예) 5분
- 재시도/실패 조건:
- 감점/실격 조건:
```

### 4-3. 문제 카드 유효 규칙

- **고정 장비만 사용**한다. 새 태그, 새 구역, 새 로봇, 새 센서를 요구하지 않는다.
- 완료 조건은 **관찰 가능한 상태**로 쓴다. “잘 정리한다”가 아니라 “빨강 퍽 2개가 RED 구역 안에 있다”처럼 쓴다.
- **QR/외부 서버/사람의 말**을 정답 전달 수단으로 쓰지 않는다.
- 퍽은 현재 키트의 **색 + 눕힘/세움** 범위 안에서 지정한다.
- 도달 불가능한 위치, 그리퍼 한계 밖 크기, 5분 안에 불가능한 양을 요구하지 않는다.
- 여러 primitive를 조합할 경우 **순서와 완료 판정**을 카드에 명시한다.
- 같은 문제가 모든 팀에 공통으로 주어질 필요는 없다. 랜덤 카드 간 난이도가 크게 다를 수 있다.

## 5. 사용 가능한 primitive

문제 카드는 아래 primitive를 조합해서 만든다.

| primitive | 의미 | 현재 태그 | 완료 예 |
| --- | --- | --- | --- |
| `NAVIGATE` | 스테이션/구역/복귀 지점으로 이동 | — | 목표 반경 안에서 정지 |
| `DETECT_TAG` | 퍽/미션/구역 AprilTag 인식 | 1,2,3,10~13,20 | 태그 ID와 자세를 로그/상태로 확인 |
| `PICK` | 퍽 집기 | — | 그리퍼가 퍽을 들고 있음 |
| `PLACE` | 퍽 내려놓기 | — | 퍽이 목표 구역/바닥에 안정적으로 놓임 |
| `SORT_COLOR` | 색별 정리 | 10 | 같은 색 퍽이 해당 색 구역에 모임 |
| `MOVE_TO_B` | B 구역으로 운반 | 11,20 | 대상 퍽이 B 구역 안에 있음 |
| `STAND_UP` | 누운 퍽 세우기 | 12 | 대상 퍽이 세워진 상태 |
| `LAY_DOWN` | 선 퍽 눕히기 | 13 | 대상 퍽이 눕힌 상태 |
| `TRAFFIC` | 신호등 조건 준수 | — | 빨강에서 정지, 초록에서 통과 |
| `AVOID` | 사람/정적 장애물 회피 | — | 충돌 없이 통과 |
| `RETURN` | 시작 지점 복귀 | — | 스폰 반경 안에서 정지 |

### 5-1. 완료 상태의 기본 정의

| 상태 | 기본 정의 |
| --- | --- |
| 퍽 세움 | 60 mm 축이 위를 향해 서 있음 |
| 퍽 눕힘 | 긴 축이 바닥과 수평 |
| 색 정리 | 같은 색 퍽이 해당 색 구역 안에 모여 있음 |
| B 구역 | 대상 퍽이 B 구역 바닥 표시 안에 있음 |
| 미션 태그 | 문제 카드가 지정한 태그 ID와 일치 |
| 복귀 | 시작 지점 반경 안에서 정지 |

정확한 판정 반경/허용 오차는 문제 카드 또는 운영진이 정한다.

## 6. 실행 계약

### 6-1. 시작

- 로봇은 시작 지점에서 정지한 상태로 출발한다.
- 시작 후 사람의 직접 조작은 없다.
- 문제 카드/활성 미션 정보는 시작 전에 고정된다.
- 로봇은 `/gz_mission/info`와 AprilTag를 통해 현재 목표를 확인할 수 있다.

### 6-2. 수행

- 로봇은 문제 카드가 지정한 순서대로 primitive를 수행한다.
- 퍽을 옮기기 전에 **대상 색/자세**를 태그로 확인한다.
- 사람 장애물은 이동 중에만 나타나므로, 미션 수행 중 정지하면 사라진다.
- 신호등이 문제 조건에 포함되면 신호를 확인하고 통과/정지한다.
- 퍽을 떨어뜨리거나 놓치면 다시 집는 재시도를 허용한다.

### 6-3. 종료

- 모든 완료 조건을 만족하고, 기본적으로 시작 지점에 복귀해 정지하면 종료.
- 문제 카드가 복귀를 요구하지 않으면 그 카드의 종료 조건을 따른다.
- 제한 시간 초과, 사람의 직접 개입, 치명적 충돌은 실패/실격 사유가 될 수 있다.

## 7. 채점 기준 (기본안)

문제 카드마다 세부 배점은 달라질 수 있지만, 공통 루브릭은 아래를 기본으로 한다.

| 항목 | 내용 | 기본 비중 |
| --- | --- | --- |
| 목표 달성 | 완료 조건을 모두 만족 | 60 |
| 정확성 | 대상 퍽/색/자세/구역을 정확히 선택 | 15 |
| 안전 | 사람·벽·장비와 심한 충돌 없음 | 10 |
| 태그/물체 보존 | 태그 훼손, 퍽 파손, 구역 밖 투척 없음 | 5 |
| 자율성 | 시작부터 종료까지 사람 조작 없음 | 5 |
| 시간 | 제한 시간 내 완료, 남은 시간 | 5 |

감점/실격 예:

- 사람과 강하게 충돌
- 퍽을 의도적으로 파손하거나 태그를 가림
- 문제 카드에 없는 미션 태그/장비를 사용
- 사람이 직접 로봇을 조작
- 완료 조건을 속이기 위해 퍽을 경기장 밖으로 제거

## 8. 예시 문제 카드 (랜덤 발제 예)

> 아래는 6개 팀이 만들 수 있는 **예시**다. 실제 문제는 이 조합에서 색·개수·순서·신호 조건이 바뀐다.

### 예시 A — “초록불에서만 배송”

- 사용: `MOVE_TO_B`, B 구역, 신호등
- 대상: red 퍽 2개
- 조건: 첫 번째 갠트리가 **초록**일 때만 통과
- 완료: 대상 퍽 2개가 B 구역 안, 사람 충돌 0
- 의도: 신호 인식 + 정지/출발 + 운반

### 예시 B — “따뜻한 색만 정리”

- 사용: `SORT_COLOR`, RED/ORANGE 구역
- 대상: red·orange 퍽, green은 건드리지 않음
- 완료: red는 RED, orange는 ORANGE에 있고 green은 원래 위치
- 의도: 색 태그 식별 + 선택적 정렬

### 예시 C — “눕힌 것만 세우기”

- 사용: `STAND_UP`
- 초기: 일부 퍽 눕힘
- 완료: 눕힌 퍽이 모두 세워짐, 원래 선 퍽은 넘어지지 않음
- 의도: 자세 판별 + 파지/회전/놓기

### 예시 D — “세운 뒤 B로”

- 사용: `STAND_UP` → `MOVE_TO_B`
- 대상: 눕힌 green 1개 + 선 red 1개
- 완료: 두 퍽이 모두 세워진 채 B 구역
- 의도: primitive 순서 조합 + 운반

### 예시 E — “사람을 피해서 복귀”

- 사용: `AVOID`, `RETURN`
- 조건: 이동 중 나타나는 사람과 충돌하지 않음
- 완료: 시작 지점 복귀, 충돌 0
- 의도: 동적 장애물 회피 + 복귀

### 예시 F — “모두 눕히고 하나만 배송”

- 사용: `LAY_DOWN` → `MOVE_TO_B`
- 대상: 모든 퍽을 눕힌 뒤, orange 1개만 B로
- 완료: 나머지는 눕힌 상태, orange는 B 구역
- 의도: 전체 상태 변경 + 선택적 운반

## 9. 금지/가정

### 금지

- QR 코드, 외부 서버, 사람의 음성/명령으로 문제를 전달하는 것
- 고정 키트에 없는 태그/구역/장비를 요구하는 것
- 퍽의 태그를 떼거나 가리는 것
- 문제 카드에 없는 퍽을 목표로 삼는 것
- 경기장 밖으로 물체를 버리는 것

### 가정

- 경기장과 장비는 시작 시 고정된다.
- 문제 카드의 1장이 무작위로 선택된다.
- 로봇은 시작 지점에서 사람 조작 없이 출발한다.
- 미션 수행 중 로봇이 정지하면 동적 사람 장애물은 사라진다.
- 신호등/사람/정적 장애물은 문제 카드에 따라 조건으로 사용될 수 있다.
- 퍽은 현재 키트의 색과 눕힘/세움 범위 안에서 지정된다.
